# Agent notes

This repo is the shared look of zirkumflex-group projects and the source of truth for it. Projects follow this repo, Flexspeak included; when a colour or token changes here, the projects catch up.

- `tokens.json` is the source of truth. Never edit `tokens.css` or `shadcn.css` by hand: change `tokens.json`, run `node scripts/build.mjs`, and commit all three.
- Run `bun run check` before committing. It fails if the generated CSS is stale, if a colour drops below its contrast floor, or if a logo SVG or a built-in product icon uses a colour `tokens.json` doesn't name.
- To change a colour, keep its contrast floor (listed in `scripts/check.mjs`) rather than loosening the floor.
- Every product shares the palette in `tokens.css` unchanged: no product hue, no `product.css`. What sets a product apart is its icon: a picture of what it is for, in the group's indigo with the caret on it and no ground of its own (the letter on the indigo tile only until one fits), made with `scripts/product.mjs` (see "A new product" in the README). The files it writes belong in the product's repo, not here, and a product never ships the group's plain indigo tile as its icon.
- `scripts/icons.js` and `scripts/glyphs.js` are loaded by `index.html` and imported by `scripts/product.mjs` and `scripts/check.mjs`. A new built-in picture goes in `icons.js`, painted by role. Keep them plain scripts with no imports. `glyphs.js` is generated by `scripts/glyphs.mjs`; don't edit it by hand.
- Status colours (`good`, `fair`, `poor`, `unknown`, `live`, `private`) mean something. Charts use `chart-1`…`chart-5`, never status colours.
- Keep everything here safe to be public: no details from private repos, no secrets.
- `index.html` is the GitHub Pages site. It reads every value from `tokens.css`; don't hard-code token colours in it.
- Logo SVGs are hand-written: keep them small, with no editor metadata. The exception is `logo/lockup*.svg`, which `scripts/lockup.mjs` outlines from Inter; rerun it rather than editing them.
